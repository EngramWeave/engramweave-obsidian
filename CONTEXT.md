# EngramWeave Obsidian Context

Shared semantics belong in [the system context](../engramweave-docs/CONTEXT.md). The native MVP follows [ADR-0015](../engramweave-docs/docs/adr/0015-mvp-direct-draft-publication.md): explicit human publication creates a new Knowledge note, retains discarded Draft files and archives their Source. Full Planner, ChangeSet, Review Note actions and Vault Git automation are outside this MVP.

The desktop-only plugin attaches to an independently running Core using a local absolute configuration path. It verifies the current Vault against Core before enabling operations and reads authentication outside the Vault; plugin settings never contain bearer tokens or model credentials. Model configuration and Analysis Profiles stay in Desktop/Core. Native Markdown editing remains in Obsidian; the plugin flushes the active editor before freezing input or requesting publication. File changes and opening the sidebar only refresh local display, never invoke models.

The sidebar shows Source Annotation, Review and Relation results, task failures and stale result provenance. User-selected Source compilation runs body generation followed by an explicit analysis attempt in the same foreground workflow. The generated Draft opens after that attempt ends only while the user is still on the initiating Source; navigation does not steal another note's focus. An existing Draft can be analyzed without repeating Compiler. Closing the plugin does not cancel Core work, and reconnecting discovers current task/publication state. Publication confirms the target path and the complete related Draft cleanup list, then delegates protected writes and recovery to Core. A disconnected request is not silently replayed with a new identifier. Transient operation errors use notices; task failures and publication conflicts remain beside their owning task or confirmation dialog.

## Core-owned rounds and explicit feedback

Analyzer presentation shows brief suggestions directly, with evidence and actual coverage folded separately. Core expands task-local short evidence IDs into file revisions and delivered segment ranges; the plugin never invents or repairs model citations. Historical optional categories and limitations remain readable. Model defaults target 0–3 high-value items with 1–2 sentences each; user templates can explicitly request more detail. API output budgets are independently configured for Compiler, Review and Relation in Desktop, not in plugin settings.

The plugin submits and observes a Core-owned Compiler/Analyzer round, including local registration; closing the plugin cannot prevent later steps from starting. Independent Retry Review and Retry Relation run only the chosen task, including explicit reruns of successful results. The sidebar reads each task's actual latest execution and shows its ID, Draft version and freshness. Changes do not force a two-task rerun; compatible reuse remains Core-owned. Minimal Recompile appends feedback to Annotation, returns pending and preserves Drafts without an immediate model call. Confirmation retains request IDs and feedback on uncertain delivery; successful acceptance clears the input. Full Idea/Integration Intent actions and diff/restore remain later work.

## Human Review selection contract

Review Complete grants planning permission to one explicitly selected Draft of a Source, without freezing its body. Before planning starts, completing review of another related Draft switches the current selection and uses that operation's Integration Intent, retaining all Draft files. The sidebar must distinguish the selected Reviewed Draft from siblings that only share the Source's reviewed stage. This full Human Review contract is separate from the implemented MVP Publish to Knowledge action.

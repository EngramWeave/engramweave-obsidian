# EngramWeave Obsidian Context

Shared semantics belong in [the system context](../engramweave-docs/CONTEXT.md). Human Review implements Review Note routing, Idea creation, Recompile, Draft-owned Intent and explicit selection/cancellation. The separate native MVP follows [ADR-0015](../engramweave-docs/docs/adr/0015-mvp-direct-draft-publication.md): explicit human publication creates a new Knowledge note, retains discarded Draft files and archives their Source. Agent Planner and candidate editing are available; full ChangeSet approval, Executor and Vault Git automation remain later P3 scope. Independent retained Drafts provide recompilation preservation; P2 does not require a cross-Draft diff, separate revision chain or rollback interface.

After P3, keep the human-approved new-note shortcut without a mandatory Planner call or another approval step, while sharing deterministic execution, archival/recovery and scoped Git commits with approved ChangeSets. The current MVP has no automatic Git; this extension remains planned. Existing accepted publication recovery must survive the transition. See [ADR-0018](../engramweave-docs/docs/adr/0018-shared-execution-for-direct-publication.md).

The desktop-only plugin attaches to an independently running Core using a local absolute configuration path. It verifies the current Vault against Core before enabling operations and reads authentication outside the Vault; plugin settings never contain bearer tokens or model credentials. Model configuration and Analysis Profiles stay in Desktop/Core. Native Markdown editing remains in Obsidian; the plugin flushes the active editor before freezing input or requesting publication. File changes and opening the sidebar only refresh local display, never invoke models.

The sidebar shows Source Annotation, Review and Relation results, task failures and stale result provenance. User-selected Source compilation runs body generation followed by an explicit analysis attempt in the same foreground workflow. The generated Draft opens after that attempt ends only while the user is still on the initiating Source; navigation does not steal another note's focus. An existing Draft can be analyzed without repeating Compiler. Closing the plugin does not cancel Core work, and reconnecting discovers current task/publication state. Publication confirms the target path and the complete related Draft cleanup list, then delegates protected writes and recovery to Core. A disconnected request is not silently replayed with a new identifier. Transient operation errors use notices; task failures and publication conflicts remain beside their owning task or confirmation dialog.

## ChangeSet candidate editing

The [Core planning contract](../engramweave/docs/planning.md) owns ready workspaces, scope checks, versions and cancellation. The plugin uses a custom ItemView with CodeMirror MergeView: the center contains only content comparison, while file selection, actions, status and explanations live in the existing right sidebar. The center compares Current with Candidate. Open original Draft opens the associated live Draft in a new native tab for user-managed comparison; missing Drafts produce a notice rather than a replacement file. No separate review snapshot, snapshot-reading endpoint or automatic change percentage is introduced; existing planning-round input freezing and recovery remain internal task behavior. Save/Ctrl+S writes only candidates; Refresh Current flushes native editors and preserves Candidate text and undo. New targets have empty Current. Preview Candidate first saves safely, then opens the corresponding file in a native Markdown reading tab with the sidebar retained; save failure or later typing prevents a stale preview. Original Drafts remain in the native editor.

Per-file buffers preserve later typing across save responses. Dirty edits are temporarily cached outside the Vault under OS application data, restored on reopen, and never sent automatically. Connection errors or version conflicts retain edits. Reload Candidate explicitly confirms loss of dirty edits before reading the current disk revision. View teardown destroys the editor and closes its confirmation dialog.

Explicit Source Restore is Core-owned and resets only the discarded Source to active/pending without starting inference; Drafts, formal content and Draft-owned Intents remain retained, while old selection and canceled ChangeSets are not restored.

The sidebar can plan the explicitly selected Reviewed Draft after flushing editors, and open ready results. Desktop opens the same view through a Vault-checked protocol link. Cancel ChangeSet returns valid selection to reviewed; Cancel Review Complete removes the proposal and returns compiled, preserving Intent. Full impact review, rejection, final approval, formal execution, archival and recovery are implemented together. Scoped Git remains D. Human choices use the Core review revision; approval saves all workspace buffers, binds displayed Current revisions and persists the original request outside the Vault before submission. Uncertain delivery exposes result lookup and original-ID retry rather than a new approval. Completed workspace reopen shows the consumed result. Nonwrite items are read-only; existing native Draft editing remains unchanged. The current implementation scope is the [local BC plan](../engramweave-docs/.local/P3/P3_BC_IMPLEMENTATION_PLAN.md) and [BC task list](../engramweave-docs/.local/P3/P3_BC_TODO.md).

Candidates are excluded from Core registration/recall. Git, Obsidian search and Sync exclusions have separate configuration, documented in the [README](README.md). No Base directory, automatic three-way merge or second editable Desktop surface is introduced.

## Core-owned rounds and explicit feedback

Analyzer presentation shows brief suggestions directly, with evidence and actual coverage folded separately. Core expands task-local short evidence IDs into file revisions and delivered segment ranges; the plugin never invents or repairs model citations. Historical optional categories and limitations remain readable. Model defaults target 0–3 high-value items with 1–2 sentences each; user templates can explicitly request more detail. API output budgets are independently configured for Compiler, Review and Relation in Desktop, not in plugin settings.

The plugin submits and observes a Core-owned Compiler/Analyzer round, including local registration; closing the plugin cannot prevent later steps from starting. Independent Retry Review and Retry Relation run only the chosen task, including explicit reruns of successful results. The sidebar reads each task's actual latest execution and shows its ID, Draft version and freshness. Changes do not force a two-task rerun; compatible reuse remains Core-owned. Recompile routes the shared Review Note into Annotation, returns pending and preserves Drafts without an immediate model call. The same input can instead create an ordinary Idea or supply the current Draft's Integration Intent. Confirmation retains request IDs and input on uncertain delivery; successful acceptance clears only the corresponding text. Existing Draft files and edits remain available in the native editor after subsequent compilation.

## Human Review selection contract

AI analysis is optional reference, not a prerequisite for Review Complete. An active Draft of a compiled or reviewed Source can be manually confirmed without any Analyzer attempt or result; the plugin does not start analysis to enable confirmation. Running Core operations retain their existing mutual-exclusion protection.

Review Complete grants planning permission to one explicitly selected Draft of a Source, without freezing its body. Integration Intent belongs independently to each Draft. Before planning starts, completing review of another related Draft switches the current selection and saves that operation's Intent for the selected Draft, retaining all other Drafts and their own Intents. Cancel and Recompile withdraw planning permission without deleting or transferring Intent; a newly compiled Draft does not inherit another Draft's Intent. The sidebar shows the open Draft's own Intent and separately identifies the selected Reviewed Draft, rather than treating every sibling as selected because its Source is reviewed. Core stores accepted human actions outside SQLite and rejects stale or conflicting writes. This Human Review contract is separate from MVP Publish to Knowledge, which consumes no Review Note and revokes planning selection on archival.

Unsubmitted Review Note text is held per Draft in memory for the plugin session; file switches, display refreshes and closing/reopening the sidebar retain it. Plugin unload, restart and application exit do not persist that unsubmitted text. A sent operation whose delivery is unknown separately retains a temporary recovery record with its original request ID and target until the outcome is known; explicit retry or result lookup avoids duplicate consumption. These records are not stored as permanent Review Notes or in Vault plugin settings, contain no credentials, and are cleaned up when resolved.

Temporary records are bounded to 32 actions under the OS application-data directory, resolved to its physical path and kept outside the Vault. The plugin never sends recovered requests during startup; Check Result and Retry Original remain explicit. Display refresh waits while the shared input has focus. An old result cannot clear later edits or another Draft's text. See [the Core Human Review contract](../engramweave/docs/human-review.md) and [backup and recovery](../engramweave/docs/recovery.md) for durable Intent backup and recovery boundaries. A normal Core restart after offline database recovery loads these accepted workflow records; opening the plugin only reads them and does not start models. Within one sidebar refresh, identical Analyzer result IDs share one request; independent IDs and subsequent refreshes retain their own fresh reads.
